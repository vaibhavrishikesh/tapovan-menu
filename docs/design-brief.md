# Tapovan Menu design brief

## Brand direction

Tapovan Menu should feel like a premium local utility for mountain cafes, not a generic food-delivery app. The design should mix warm cafe textures with clean SaaS clarity.

**Core promise:** Printed menu + live availability.

**Primary line:** One platform. Many cafes.

**User-facing line:** Scan once. See what is actually available.

## Visual system

| Element | Direction |
| --- | --- |
| Colors | Forest green, cream, warm amber, charcoal, soft red for unavailable |
| Feel | Local Tapovan, mountain cafe, clean operator dashboard |
| Typography | Friendly modern sans for app UI; optional handwritten accent only in marketing hero |
| Icons | QR, menu, leaf/ingredient, bell/status, analytics |
| Layout | Cards, clear status chips, owner-friendly dashboards |

## Key demo screens

1. **Pitch hero**: Tapovan Menu logo, printed menu + QR, phone live menu and admin dashboard.
2. **Owner onboarding**: create outlet, add logo, location and contact details.
3. **Menu builder**: add categories, dishes, prices and photos.
4. **Ingredient mapping**: link ingredients to dishes.
5. **Daily availability control**: quick toggles for ingredients and dishes.
6. **Customer live menu**: outlet name header, area label, live status, available dishes first, unavailable dishes clearly labeled.
7. **QR poster generator**: printable table card/counter card.
8. **Analytics dashboard**: scans, sold-out items and missed demand.

## Product rules for the design

- The product is named **Tapovan Menu** everywhere.
- It is one shared platform for many cafes, hotels and hostels.
- Each outlet gets its own QR and live menu page.
- Admin users update ingredients first; dish status can update automatically.
- The customer menu should show the cafe/restaurant name, area and live status before the item list.
- The customer menu should be simple enough for tourists to understand in seconds.
- The admin panel should feel like a daily counter tool, not a heavy restaurant ERP.
